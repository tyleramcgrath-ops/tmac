# State bar importer

Builds LawMatchNow attorney profiles from a state bar's public membership
records, so the directory lists real, licensed lawyers. Profiles are created
unclaimed: the attorney can claim and edit theirs. Florida is the first state.

Every run is a **dry run** unless you add `--apply`. It writes a report folder
(`reports/…`) showing what would happen before anything changes.

## 1. Get the file from The Florida Bar

Request it with the Bar's
[Public Records Request for Florida Bar Membership Data](https://www.floridabar.org/about/faq/rec-request/)
form, emailed to `membershipdatarequest@floridabar.org`. On the form choose:

- **Entity type:** Only eligible MIGS (members in good standing who can practice)
- **Location:** In State only
- **Circuit(s):** All Circuits
- **Comments:** "Please include each member's admission date."

The Bar emails back an Excel file with bar number, name, firm, address,
phone, email, county and circuit.

For practice areas, send a second request with **Board Certification(s): All
Board Certifications**. That list only contains board-certified members, so
it can't replace the main file. Pass it with `--certifications`, and each
member's certifications are shown on their profile and mapped to practice
areas (Marital and Family Law → Family Law, Criminal Trial → Criminal
Defense, and so on; see `lib/florida.mjs`).

The Bar notes that this data doesn't give consent to unsolicited contact.
Use it to list attorneys, not to cold-email them.

## 2. Set up

Requires Node 20 or newer.

```sh
cd apps/lawmatchnow/tools/bar-import
npm install
export LMN_API_URL=https://vc953650138104.coderick.net
```

For `--apply` you also need a PocketBase superuser login (the one used at
`/_/`):

```sh
export PB_ADMIN_EMAIL=...
export PB_ADMIN_PASSWORD=...
```

The API host sits behind SiteGround's anti-bot check, which challenges some
networks. If a run fails with "202 … sgcaptcha", run the importer from the
SiteGround server over SSH, or from a different network. (Behind an HTTP
proxy, set `NODE_USE_ENV_PROXY=1` so Node uses it.)

Writing about 80,000 profiles takes roughly an hour at the default 6
parallel requests.

## 3. Clear out the placeholder listings (once)

About 65,000 records were generated by the old site, with made-up 555 phone
numbers and names like "Jordan Peterson 39890". They're already hidden from
visitors, but they take up web addresses (`jane-doe-miami`) that real
attorneys should get. Remove them before the first import:

```sh
node import.mjs purge-placeholders                         # dry run: count + examples
node import.mjs purge-placeholders --also-empty-contact --apply
```

Only records with **no bar number that were never claimed** are touched:
555 phone numbers, plus (with `--also-empty-contact`) ones with no phone and
no address. A full copy of every matched record is saved to `backup.json` in
the report folder before anything is deleted.

## 4. Import Florida

```sh
node import.mjs florida members.xlsx --certifications certifications.xlsx --as-of 2026-11-02
```

Check `reports/florida-…-dry-run/`:

- `summary.json`: rows read, skipped (and why), new profiles, updates, top cities
- `preview-new.json`: the first 50 profiles exactly as they'd be saved
- `skipped.csv`: members left out and the reason

Then write a small test batch, look at a few profiles on the site, and do the rest:

```sh
node import.mjs florida members.xlsx --certifications certifications.xlsx --as-of 2026-11-02 --add-source-fields --limit 25 --apply
node import.mjs florida members.xlsx --certifications certifications.xlsx --as-of 2026-11-02 --apply
```

`--as-of` is the date the Bar produced the file. Profiles say "compiled from
The Florida Bar's public membership records (November 2026)".

### What gets imported

| Directory field | From the Bar file |
| --- | --- |
| name | Name, cleaned up (`SMITH, JOHN ALLEN JR.` → `John A. Smith, Jr.`) |
| firm, address, city, ZIP, phone | As listed, title-cased and formatted |
| bar_number | `FL-<number>`: the key that matches re-imports to existing profiles |
| bar_admissions | `Florida (Bar No. 123456, admitted 2004); Board Certified: …` |
| years_experience | From the admission year, when the file has one |
| practice_areas | From board certifications only; never guessed |
| bio | A short factual note naming the source and date |

**Skipped:** members with an office outside Florida (`--include-out-of-state`
keeps them), government offices, courts, legal aid and universities that
don't take private clients (`--keep-not-for-hire` keeps them), anyone with
neither a phone nor a firm, and any row whose status reads inactive,
suspended, retired or similar.

**Emails** are not stored by default: the public API would hand them to
anyone. To store them for claim verification, first set the `email` field to
**Hidden** in PocketBase, then add `--with-email`.

### Re-running with a newer file

Run the same command with the new file. Members are matched by bar number:

- **New members** are added.
- **Changed details** (a new firm or phone) are updated.
- **Claimed profiles are never changed.** The attorney maintains them.
- **Members missing from the new file** (resigned, retired, deceased) are
  listed in `not-in-file.csv` for review, not deleted.
- **Web addresses never change** once created, so links and search results keep working.

## Adding another state

Copy `lib/florida.mjs` to `lib/<state>.mjs`. Adjust `STATE`, the column
aliases, the certification list and any "not for hire" patterns. Then
register the adapter in `import.mjs` (`commands`).

## Tests

```sh
npm test
```

Unit tests cover the name, phone and column handling. An end-to-end test
runs the real script against an in-memory PocketBase in four steps: a dry
run, an apply, a re-run that must change nothing, and the purge.
