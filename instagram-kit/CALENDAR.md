# Posting order

Twelve posts, three a week, four weeks. Order matters more than dates: the
account opens by saying who this is, then alternates between a service post and
a post that teaches something, so the grid never reads as four adverts in a row.

If you post less often, keep the order and stretch it. Do not start in the
middle — post 1 is written to be the first thing a new visitor sees, and it is
the one to pin to the top of the grid.

## Notes

**Stories.** Each feed post can be reshared to a story on the day it goes up.
That is also what makes the highlight covers usable — a highlight can only hold
stories that have already been posted.

**Hashtags go in the first comment**, not the caption. Every post has its block
ready in `CAPTIONS.md`.

**Spacing.** Leave a few hours between posts rather than publishing several in
one sitting. Rapid-fire posting from a browser session is a common way to
trigger a temporary action block.

**After the twelve.** The site holds far more than this kit uses — the FAQ
blocks on each page are twenty-plus more questions, each of which is a carousel
in the shape of posts 8, 9 and 11. Add them to `posts.json` and re-run
`build.py`.
